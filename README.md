# MaizeDetection

A corn-leaf foliar-disease **image classifier** built to do one thing honestly:
train a strong transfer-learning baseline on *controlled* lab images, then
**measure how badly it generalizes to real field photos** of the same diseases.

> **The domain gap is the deliverable, not the accuracy number.**
> In-domain accuracy is **98.4%**. On field images of the same two diseases it
> falls to **61.7%**, and a quarter of diseased field leaves get silently called
> "healthy." That gap — measured and reported transparently — is the point.

---

## TL;DR findings

| | Controlled (PlantVillage, held-out test) | Field (CD&S, NLB + GLS) |
|---|---|---|
| **Accuracy** | **0.984** (4-class) | **0.617** (restricted 2-class) · 0.465 (open 4-way) |
| **NLB recall** | 0.957 | 0.563 → **−0.39** |
| **GLS recall** | 0.973 | 0.667 → **−0.31** |
| **Worst failure** | NLB↔GLS confusion (a few leaves) | **26.2%** of diseased leaves predicted *healthy* |

The same model, the same preprocessing — only the **domain** changed. The
published CD&S benchmark reports ~94% → ~55% for gray leaf spot; our gap is of
the same character, reproduced rather than tuned toward.

---

## What this is (and is not)

A 4-class corn foliar-disease classifier over the canonical labels:

```
healthy   common_rust   northern_leaf_blight   gray_leaf_spot
```

It is **not** a treatment recommender, a severity/yield estimator, an
object-detection/drone system, or a medical-style diagnosis tool. It is a
transfer-learning classifier whose research value is the honest controlled-vs-field
comparison. The model is trained by us (an ImageNet EfficientNet-B0 backbone + our
own 4-class head + our own pipeline), **not** dropped in from a pre-finetuned Hub
checkpoint.

## Results in detail

### In-domain — controlled PlantVillage test split (leaf-grouped, never seen in training)

Checkpoint: phase B, epoch 13, val_loss 0.0421. **Accuracy 0.984 · macro-F1 0.978.**

| class | precision | recall | F1 | **FN-rate** | n |
|-------|----------:|-------:|---:|------------:|--:|
| healthy | 1.000 | 1.000 | 1.000 | **0.000** | 168 |
| common_rust | 1.000 | 0.994 | 0.997 | **0.006** | 179 |
| northern_leaf_blight | 0.978 | 0.957 | 0.968 | **0.043** | 141 |
| gray_leaf_spot | 0.923 | 0.973 | 0.947 | **0.027** | 74 |

The only meaningful in-domain errors are NLB↔GLS confusion (both are lesion
diseases). **FN-rate = 1 − recall** — the fraction of truly-diseased leaves the
model *missed* — is the metric we lead with, because a missed disease is worse
than a false alarm.

> ⚠️ `common_rust`'s near-perfect score is the one to distrust. Corn has no
> official `leaf_id`, so we derive one from filenames; for rust every image is its
> own "leaf," so a same-leaf train/test leak **cannot be ruled out**. Treat that
> 0.994 recall as possibly optimistic (the `COMMON_RUST_LEAKAGE_CAVEAT` is printed
> on every eval run so it can't be dropped).

### Cross-domain — CD&S field images (1,020 photos: NLB 497, GLS 523)

CD&S has no healthy and no common_rust class, so this is a 2-class field test. The
same forward pass is reported **two ways**:

**View 1 — Open 4-way** (model may emit any of its 4 classes; exposes deployment behavior):

| class | recall | FN-rate | n |
|-------|-------:|--------:|--:|
| northern_leaf_blight | 0.362 | 0.638 | 497 |
| gray_leaf_spot | 0.562 | 0.438 | 523 |

**Leakage error mode: 267 predictions (26.2%) landed outside the field classes —
264 → `healthy`, 3 → `common_rust`.** Calling a diseased field leaf *healthy* is
the most dangerous failure for a detection tool, and only the open view reveals it.

**View 2 — Restricted 2-class** (decision forced to the NLB-vs-GLS logits; isolates the surviving signal):

| class | precision | recall | F1 | FN-rate | n |
|-------|----------:|-------:|---:|--------:|--:|
| northern_leaf_blight | 0.617 | 0.563 | 0.589 | 0.437 | 497 |
| gray_leaf_spot | 0.617 | 0.667 | 0.641 | 0.333 | 523 |

**Accuracy 0.617 · macro-F1 0.615.** Restricting to the two trained-on diseases
recovers some of the leaked predictions, but recall still drops ~0.3–0.4 per class
versus controlled.

### Why the gap?

Controlled PlantVillage images are single detached leaves on uniform backgrounds;
backgrounds even correlate with class. The model learns shortcuts (lighting,
framing, background tone) that simply do not exist in handheld field photos with
natural clutter. This is exactly the generalization failure the project set out to
quantify.

Artifacts (regenerated by the eval commands below, git-ignored under `outputs/`):
`metrics_in_domain.json`, `metrics_cross_domain.json`, and confusion-matrix PNGs.

## Setup

**Requirements:** Windows (developed on), Python **3.12** (avoid 3.13+ for V1),
`venv`. Training can use a Colab/Kaggle GPU; **local inference runs on CPU.**

```powershell
# 1. Create and activate a virtual environment
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 2. Install the CPU build of PyTorch FIRST (from the official selector)
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu

# 3. Install everything else
pip install -r requirements.txt

# 4. Sanity-check the environment (must confirm .venv + all imports)
python scripts/check_env.py
```

## Reproduce the pipeline

```powershell
# --- Data ---
python scripts/download_plantvillage.py        # ~2 GB to HF cache; extracts 4 corn classes
python scripts/download_cds.py --verify        # CD&S field images from OSF; builds overlap dir

# --- Leak-safe splits (70/15/15, grouped by leaf_id) ---
python -m src.maize_detection.data             # writes data/processed/plantvillage_splits.csv

# --- Train (GPU strongly recommended: use notebooks/02 on Colab) ---
python -m src.maize_detection.train            # → outputs/checkpoints/best.pt
#   smoke test: --max-batches 2 --epochs-a 1 --epochs-b 1

# --- Evaluate ---
python -m src.maize_detection.evaluate         # in-domain → metrics_in_domain.json + figure
python -m src.maize_detection.cross_evaluate   # field gap → metrics_cross_domain.json + figures
```

A full 20-epoch run (5 frozen + 15 fine-tune) is impractical on CPU — train on
Colab via `notebooks/02_train_baseline.ipynb`, then drop the downloaded `best.pt`
into `outputs/checkpoints/`. The repo does **not** ship trained weights
(checkpoints are git-ignored); you produce your own.

> On Windows, if torch crashes with an OpenMP/MKL DLL error, set
> `$env:KMP_DUPLICATE_LIB_OK="TRUE"` before running.

## Using the model

Once `outputs/checkpoints/best.pt` exists, classify any leaf image on CPU:

**Python API**
```python
from src.maize_detection.predict import predict

result = predict("path/to/leaf.jpg")
# {
#   "label": "gray_leaf_spot",
#   "confidence": 0.996,
#   "probabilities": {"healthy": 0.002, "common_rust": 0.0,
#                     "northern_leaf_blight": 0.001, "gray_leaf_spot": 0.996}
# }
```

The checkpoint is loaded once and cached across calls; pass a preloaded `model=`
for batch loops. Preprocessing uses the pretrained weights' own `.transforms()`,
so inference never drifts from training.

**Command line**
```powershell
python -m src.maize_detection.predict path/to/leaf.jpg
```

> ⚠️ **Read the field result above before trusting any prediction.** This model was
> trained on controlled images; on real field photos it is unreliable (≈0.62
> accuracy, and it misreads many diseased leaves as healthy). A high `confidence`
> is **not** a guarantee of correctness. It is a research classifier, not a
> diagnostic tool.

## Datasets

| dataset | role | type | source |
|---------|------|------|--------|
| **PlantVillage** (corn, color) | training + in-domain test | controlled lab leaves | HuggingFace `mohanty/PlantVillage` |
| **CD&S** `Dataset_Original` | cross-domain eval (NLB + GLS) | field photos, iPhone, Purdue ACRE | OSF `s6ru5` |

Label integrity is enforced: Northern Leaf **Spot** ≠ Northern Leaf **Blight**,
Southern Rust ≠ Common Rust. Non-overlapping external classes (CD&S's NLS) are
**excluded**, never force-mapped; `validate_mapping()` hard-fails on a bad mapping.

## Testing

```powershell
python -m pytest -q        # 40 tests
```

The suite guards the project's invariants, most importantly **zero `leaf_id`
intersection across train/val/test** (the cardinal anti-leakage rule), plus label
mapping integrity, metric correctness (incl. FN-rate = 1 − recall), and the
`predict()` output contract. Tests that need a checkpoint/images skip cleanly when
those assets are absent, so a fresh clone still passes.

## Methodology & invariants

1. **leaf_id leakage is the cardinal sin.** Every split is grouped by `leaf_id` so
   no physical leaf appears in two splits; a test asserts zero overlap.
2. **Never mis-map labels.** Biologically distinct diseases are never merged.
3. **We train the model.** ImageNet backbone only; the disease head is ours.
4. **Preprocessing matches.** Eval/inference use the weights' own `.transforms()`.
5. **Report controlled vs field together.** Lead with the gap; always include
   per-class false-negative rate.

Full rationale: `MaizeDetection_V1_Implementation_Plan.md` and `CLAUDE.md`.
